# PDF 문서 청킹 기술 보고

## 1. 요약

KMS 시스템은 245개 PDF 매뉴얼(19개 제품)을 AI가 정확하게 검색할 수 있도록 "청킹(Chunking)"이라는 문서 분할 기술을 적용하였습니다. 일반적인 RAG 시스템이 문서를 단순히 일정 글자 수로 잘라 사용하는 반면, 본 시스템은 PDF 문서의 목차 구조를 인식하여 의미 단위로 분할하는 방식을 채택했습니다.

이를 통해 "tjesmgr BOOT 명령어를 설명해주세요"라는 질문에 BOOT 명령어 섹션만 정확히 반환하고, 관련 없는 다른 명령어 정보가 섞이지 않습니다.

---

## 2. 기존 방식의 한계

일반적인 RAG 시스템에서 사용하는 고정 크기 청킹(예: 500자씩 분할)은 다음과 같은 문제가 있습니다.

| 문제 | 설명 | 결과 |
|------|------|------|
| 문맥 단절 | 명령어 설명 도중에 잘려서 앞부분만 검색됨 | 불완전한 답변 |
| 정보 혼입 | ALTER 명령어와 DEFINE 명령어가 하나의 청크에 섞임 | 잘못된 답변 (Hallucination) |
| 구조 손실 | "제6장 > 데이터셋 명령어 > DSCOPY"라는 계층 정보가 사라짐 | 출처 추적 불가 |
| 노이즈 포함 | 표지, 목차, 저작권 페이지도 검색 대상에 포함 | 검색 정확도 저하 |

---

## 3. 본 시스템의 청킹 방식

### 3.1 핵심 기술: PDF 목차(TOC) 기반 의미 분할

PDF 파일에 내장된 목차(Table of Contents) 메타데이터를 활용하여 문서의 장/절/항 구조를 자동으로 인식합니다. 이를 통해 각 섹션의 시작 페이지와 종료 페이지를 정확히 파악하고, 의미 단위로 분할합니다.

예시 (TJES Guide):

```
원본 PDF 목차 구조:
  제6장 TJESMGRコマンド
    ├─ ジョブ実行コマンド
    │    ├─ CANCEL
    │    ├─ HOLD
    │    └─ BOOT
    ├─ データセット・コマンド
    │    ├─ DATASETCOPY
    │    └─ DATASETCREATE
    └─ その他のコマンド
         ├─ HELP
         └─ VERSION
```

위 구조를 인식하여 BOOT 명령어는 "TJESMGRコマンド > ジョブ実行コマンド > BOOT"이라는 계층 제목과 함께 독립된 청크로 분리됩니다.

### 3.2 사용 라이브러리

| 라이브러리 | 역할 |
|-----------|------|
| PyMuPDF (C++ 기반) | PDF 파일 파싱, 목차 추출, 텍스트/이미지/테이블 추출, 음영 영역 감지 |
| Python 표준 라이브러리 | 정규식 기반 다국어 토큰화, 수학 함수(IDF 가중치), 파일 탐색 |

외부 의존성은 PyMuPDF 하나뿐이며, 검색에 LLM(대규모 언어모델)이나 임베딩 모델을 사용하지 않습니다. 이로 인해 검색 결과가 항상 동일하게 재현되며(결정론적), 추가 GPU 자원이 불필요합니다.

### 3.3 주요 처리 기법

(1) 3단계 계층 파싱

PDF 목차의 L1(장), L2(절), L3(항) 구조를 인식하여 최하위 단위까지 분할합니다. 상위 항목(예: "제6장")은 하위 항목이 세분화된 내용을 제공하므로 중복 추출하지 않고, 개요 텍스트만 별도로 저장합니다.

(2) 대규모 섹션 자동 분리

하나의 섹션이 8,000자를 초과하면 내부의 대문자 명령어 패턴(ALTER, DEFINE, LISTCAT 등)을 감지하여 서브커맨드 단위로 자동 분리합니다. 이를 통해 "IDCAMS 명령어" 섹션(12,000자)이 ALTER(2,500자), DEFINE(3,200자) 등으로 세분화됩니다.

(3) 코드블록 자동 감지

PDF 매뉴얼에서 명령어 예시, 출력 결과 등은 회색 배경 영역으로 표시되어 있습니다. PyMuPDF의 드로잉 분석 기능으로 이 음영 영역을 자동 감지하여 코드블록으로 변환합니다. TJES Guide 138개 섹션 중 109개(79%)에서 코드블록이 추출되었습니다.

(4) 테이블 인라인 렌더링

PDF 내 테이블을 Markdown 형식으로 변환하여 검색 결과에 포함합니다. 성능 최적화를 위해 초기 로딩 시에는 테이블을 추출하지 않고, 검색 결과에 포함된 페이지만 대상으로 지연 추출(Lazy Extraction)합니다.

(5) 노이즈 자동 제거

표지, 목차, 저작권, 개정이력 등 검색에 불필요한 전면부(Front Matter)를 자동으로 제외합니다. 또한 반복 출현하는 헤더/푸터(3회 이상 동일 줄)도 자동 제거합니다.

(6) 다국어 검색 지원

일본어(한자, 카타카나, 히라가나), 한국어, 영어를 구분하여 토큰화하며, 약 60개의 불용어(조사, 접속사, 기능어구)를 제거하여 의미 있는 키워드만으로 검색합니다.

---

## 4. 검색 알고리즘

검색은 IDF(Inverse Document Frequency) 가중치 기반의 키워드 매칭 방식을 사용합니다.

| 단계 | 설명 |
|------|------|
| 토큰화 | 쿼리를 다국어 키워드로 분리 (불용어 제거) |
| IDF 계산 | 희소한 키워드(제품명, 명령어명)에 높은 가중치 부여 |
| 점수 부여 | 섹션 제목 매칭 시 3배 가중, 본문 매칭 시 1배 |
| 커버리지 보정 | 쿼리 키워드가 모두 매칭될수록 높은 점수 |
| 도메인 우선순위 | PDF 원본(1.5배) > 명령어 요약(1.3배) > 학습 데이터(0.4배) |
| 중복 제거 | 동일 내용이 여러 소스에서 검색되면 1건만 반환 |

이 방식은 LLM을 사용하지 않으므로 동일 질문에 항상 동일한 결과를 반환하며, 10ms 이내에 검색이 완료됩니다.

## 5. 성과

### 5.1 청킹 품질

| 지표 | 결과 |
|------|------|
| 처리 대상 | 245개 PDF, 19개 제품 |
| TJES Guide (146p) 청킹 | 138개 섹션, 243,537자, 365ms |
| 코드블록 추출률 | 79% (138개 중 109개 섹션) |
| 섹션 평균 크기 | 1,764자 (적정 범위) |
| 파싱 소요 시간 | 제품당 1~5초 (1회만 실행, 이후 메모리 캐시) |
| 검색 소요 시간 | 10ms 이내 |

### 5.2 Hallucination 방지 효과

청킹 품질 향상은 Hallucination(환각) 방지에 직접적으로 기여합니다.

| 항목 | 이전 (고정 크기 청킹) | 현재 (TOC 기반 청킹) |
|------|---------------------|---------------------|
| 정보 혼입 | 빈번 (다른 명령어 정보 섞임) | 없음 (섹션별 격리) |
| 문맥 단절 | 빈번 (중간에 잘림) | 없음 (의미 단위 분할) |
| E2E 테스트 통과율 | 53% (24/45건) | 100% (40/40건) |
| 구조화 질문 Hallucination | 발생 | 0% (Template 모드) |

### 5.3 시각화 도구

청킹 결과를 검증하고 품질을 관리하기 위해 PDF Chunk Visualizer CLI 도구를 개발했습니다.

제공 기능:
- 청킹 결과를 인터랙티브 HTML 대시보드로 시각화
- 섹션별 크기 분포, 코드블록/테이블 포함 여부 확인
- PDF 목차 트리 뷰와 청킹 결과 대조
- 검색 시뮬레이션 (실제 검색 알고리즘으로 쿼리 테스트)
- 여러 PDF 일괄 처리 및 비교 요약

---

## 6. 결론

본 시스템의 PDF 청킹 기술은 단순한 텍스트 분할이 아닌 문서 구조 인식 기반의 의미 분할을 구현했습니다. PyMuPDF 라이브러리의 목차 파싱, 드로잉 분석, 블록 좌표 추출 기능을 활용하여 다음을 달성했습니다.

- 목차 구조를 활용한 정밀 분할로 명령어별 정확한 검색 가능
- 코드블록과 테이블을 원문 형태 그대로 보존
- LLM 비의존 검색으로 결과 재현성 확보 및 GPU 자원 절감
- 10ms 이내 검색 속도로 실시간 응답 가능
- E2E 테스트 100% 통과 (Hallucination 제로)

이러한 청킹 품질은 RAG 시스템 전체의 답변 정확도를 좌우하는 핵심 요소이며, 상용 RAG 솔루션 대비 도메인 특화된 높은 수준의 검색 품질을 제공합니다.
